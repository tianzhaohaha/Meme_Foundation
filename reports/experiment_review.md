## 效率：整体成本与第二阶段分开看

| 方案 | 完整训练循环时间 | 完整方案阶段耗时 | 七分类阶段训练时间 | 七分类阶段总耗时 |
|---|---:|---:|---:|---:|
| V1 | 995.80秒（16.60分） | **1,064.39秒（17.74分）** | 995.80秒 | 1,064.39秒 |
| V2 | 1,121.29秒（18.69分） | 1,259.78秒（21.00分） | **198.40秒** | **267.23秒** |
| V3 | 1,183.00秒（19.72分） | 1,393.32秒（23.22分） | 260.11秒 | 400.77秒 |

共享二分类阶段训练循环耗时922.89秒，阶段总耗时992.55秒。V2/V3的完整方案成本都计入这一前置成本；实际队列只训练了一次它。V3的实际新增计算是400.77秒的第二阶段，而非再次支付整个二分类阶段。把V3的新增成本400.77秒与V2包含预训练的1,259.78秒直接比较，会混淆口径。

`train_seconds`包含训练循环的数据读取、前向、反向、优化和定期日志；阶段总耗时还包含模型设置、验证、checkpoint保存和最终测试，不含外部数据预处理及W&B最后上传等待。实际进程/队列耗时还会包含Python启动、缓存检查、外部checkpoint哈希核验等开销，不要求与阶段计时严格相等。

重点比较V2、V3的第二阶段：

| 指标 | V2 整体微调 | V3 冻结主干 |
|---|---:|---:|
| 训练样本 | 5,000 | 5,000 |
| 实际epoch | 6 | 20 |
| 优化器步数 | 1,878 | 6,260 |
| 平均每轮训练循环 | 33.07秒 | **13.01秒** |
| 平均每轮含验证/保存 | 42.31秒 | **19.39秒** |
| 平均每步 | 105.65毫秒 | **41.55毫秒** |
| 吞吐量 | 151.21样本/秒 | **384.45样本/秒** |
| 峰值allocated GPU显存 | 5.232 GiB | **0.974 GiB** |
| 可训练参数 | 210,249,479 | **1,799** |
| 总验证耗时 | 30.41秒 | 101.39秒 |
| 总checkpoint保存耗时 | 25.07秒 | 26.24秒 |

冻结后吞吐量为V2的 **2.54倍**，显存下降 **81.39%**，每轮计算明显更便宜。但V3训练了20轮，而V2在6轮早停，所以V3的第二阶段训练总时间增加 **31.10%**，阶段总耗时增加 **49.97%**。固定比较前6轮时，V3只需约78.38秒训练时间，验证accuracy为39.75%；V2用了198.40秒，最佳验证accuracy为54.65%。效率优势需要连同效果一起解释。

V3的完整方案峰值显存仍约5.23 GiB，因为它的二分类预训练阶段是全参数训练；0.974 GiB只描述冻结后的第二阶段。

## 收敛与类别表现

V1在第2轮达到最佳验证accuracy 57.55%，累计训练332.21秒；之后到第6轮降至50.25%。同时训练loss从第2轮1.1867升至第6轮1.3529，验证loss也上升。这不能仅用“训练越来越好、验证越来越差”的典型过拟合解释，后续需要检查学习率、Adam耦合weight decay和训练稳定性；目前不能把原因确定为某一项，也不应仅增加epoch。

V2同样在第2轮达到最佳验证accuracy 54.65%，第二阶段累计训练66.22秒。后续训练loss继续下降，验证accuracy停留在53.5%–54.3%左右，呈现泛化收益停滞。它在已有二分类模型时能很快得到可用的七分类模型，但完整计算成本仍需计入预训练。

V3从12.9%验证accuracy逐渐升至41.65%，第18轮首次达到最高值；第20轮只是持平，因使用严格提升规则，`best.pt`仍保留第18轮。这次是达到20轮上限结束，并非早停。三版七分类都没有达到配置中的80%验证accuracy目标，达标时间为null；不能把二分类达到80%的时间用于七分类效率比较。

| 测试召回率 | V1 | V2 | V3 |
|---|---:|---:|---:|
| Angry | 50.00% | 37.07% | **0.00%** |
| Bored | 62.75% | 70.31% | 69.47% |
| Calm | 66.31% | 49.20% | 18.72% |
| Fear | 56.74% | 52.09% | **6.05%** |
| Happy | 65.71% | 70.38% | 84.56% |
| Love | 48.55% | 30.92% | **4.91%** |
| Sad | 40.99% | 40.09% | 26.13% |

V3从未预测Angry；它把84.1%的测试样本预测为Happy或Bored。这解释了42.10% accuracy与0.2633 macro-F1之间的差距：整体准确率掩盖了多个类别的识别失败。仅观察显存和训练速度会漏掉这项代价。

把已有七分类混淆矩阵合并成正/负两组后，V1/V2/V3分别得到83.15% / 82.35% / 83.90%。这是七分类预测的事后聚合，**不是共享二分类checkpoint的测试结果**。它支持一个解释：冻结的特征仍能区分粗粒度正负情绪，但对细粒度类别不足；因没有额外消融，尚不能证明瓶颈只来自融合层或某一个编码器。

## 使用建议与结论边界

- 本次已有全部25,000条七分类标签、追求最终效果时，使用V1的第2轮 `best.pt`。
- 已经拥有二分类源模型、只有5,000条七分类标注时，V2比V3更值得优先使用；额外微调阶段约4.45分钟，测试accuracy 54.30%。
- V3适合研究显存/反向传播成本约束，但当前checkpoint有明显类别偏置，不宜仅凭42.10% accuracy认定其七类都可用。
- 后续实验可在固定验证集上尝试“冻结两个编码器，但允许融合层和七分类头更新”，或逐层解冻；这会成为新策略，不应覆盖本次V3。对于V1先检查训练loss回升的原因，再决定调整学习率或优化器设置。

当前只有seed42，不能声称3.35个百分点的差异已通过统计显著性检验；没有保存逐样本预测，也不能仅靠聚合混淆矩阵做配对检验。模型选择仍须使用验证集，不能根据本次测试集指标反复调参。训练清单之间仍有227个相同图片哈希；验证/测试已排除图片及规范化非空文本重复，但没有完整近重复或跨用户分组审计。

完整数值可从 [聚合JSON](data/seed42.json) 与 [CSV](comparison.csv)读取；图表可用 `python tools/plot_results.py` 重绘。本报告不把单个seed结果推广为所有任务、数据预算或超参数下的结论。
